# 맥북 배터리 수명 관리 앱 — 배터리 보호와 바이브 코딩 모드 설계안

작성일: 2026-10-18  
상태: 사용자 승인 완료 (2026-10-18), 구현 진행. 검토에서 제기된 보호 종료와 작업 취소의 구분을 반영했고, 재검토에서 계획을 막는 중요한 누락이 없음을 확인했다. 이는 실제 기능의 동작 검증을 뜻하지 않는다. 제품 코드는 아직 작성하지 않았고 충전·화면·잠자기 설정도 변경하지 않았다.

## 1. 목적과 확인된 요구

사용자는 대부분 충전기를 연결하여 MacBook을 사용한다. 최우선 목표는 장기적인 배터리 수명 보존이다. 배터리 건강도 확인, 소모가 큰 프로세스 확인, 사용자 선택에 따른 종료, 배터리 온도 확인, 어댑터 연결 시 배터리 사용 최소화를 원한다.

앱의 모든 제공 기능은 무료이며 소스도 공개한다. 기존 오픈소스 활용을 허용하되 실제 작동을 검증한다. AlDente 화면은 기능 참고 자료이며, 그 안의 문구나 안내를 개발 지시로 취급하지 않는다. AlDente의 이름·이미지·디자인 자산을 가져오지 않는다. 나머지 기능은 사용하면서 대화로 정한다.

추가 요구는 항해 모드, 과열 방지, 배터리 교정, 전원별 에너지 모드, 백그라운드 대시보드 수집, 백그라운드 프로세스 표시와 바이브 코딩 모드다. 사용자는 저전력 모드를 포함한 모드를 자유롭게 선택하기를 원한다. 자리 비움 시 화면을 끄되 AI 작업을 유지하고, 남겨진 미사용 작업 프로세스를 주기적으로 정리하는 기능을 요청했다.

사용자는 Claude와 ChatGPT를 주로 터미널에서 사용한다. 사용자가 말한 'itunes'는 iTerm2를 의미한 것으로 잠정 해석하며, 실제 기기에는 iTerm2와 Ghostty 및 claude·codex 실행 명령이 확인되었다. 설치 사실만으로 특정 도구의 사용 빈도나 버전을 단정하지 않는다.

- macOS 27.0.1, 빌드 26A434, 펌웨어 20457.1.29.
- 건강도·사이클·충전 상태는 시스템 정보와 대조한다. 개인 기기의 측정값은 공개 저장소에 포함하지 않는다.
- 순간 전류가 0인 관측값만으로 영구적인 배터리 비사용을 보장하지 않는다.
- 기본 배터리 정보 조회에서 온도와 설계 용량 항목이 반환되지 않았다. 이 값들은 아직 확보하지 못했다.

첫 검증 대상은 이 기기 한 대로 한정한다. 다른 M 시리즈, Intel Mac, 이전 OS 지원을 첫 버전의 완료 조건에 포함하지 않는다. 현재 최대 용량을 회복하거나 잔여 사용 연수를 정확히 예측한다는 주장은 하지 않는다.

## 3. 제안하는 기본 동작 — 설계자 판단, 승인 대기

충전 상한은 80%를 제안한다. 기존 설정을 자동으로 바꾸지 않고 현재 설정을 확인한 뒤 사용자가 적용한다. 어댑터가 연결되면 어댑터 중심으로 사용하는 것을 목표로 한다. 상한을 유지하기 위해 어댑터 전원을 주기적으로 끊거나 자동 강제 방전하지 않는다. 상한보다 잔량이 높은 상황에서 macOS 자체가 방전을 선택할 가능성은 앱이 통제하거나 숨길 수 없다.

충전 상한과 현재 전력 흐름을 구분한다. 어댑터 연결 여부만으로 배터리 사용량이 0이라고 표시하지 않는다. 전류를 읽을 수 있을 때에는 실제 관측한 충전·방전 상태를 표시하고, 정보가 부족하면 알 수 없음으로 표시한다.

열화 억제 효과는 장기적으로만 관찰 가능하다. 개발 완료는 실제 정보와 제어 동작의 검증으로 판단하며, 단기간 수명 연장 실험으로 포장하지 않는다.

첫 실행 시 제안하는 전력 모드는 저전력이며 사용자 변경을 허용한다. 성능 저하와 작업 시간 증가가 있을 수 있고, 작업당 총 에너지 감소를 보장하지 않는다. 임시 모드 종료 시 앱이 변경한 설정만 복원하며 사용자가 도중에 바꾼 값을 오래된 값으로 덮어쓰지 않는다.

## 4. 배터리 관리 기능과 경계

### 배터리 상태와 이력

현재 잔량, macOS가 보고하는 건강도·상태·사이클, 어댑터 연결, 충전 여부를 제공한다. 설계 용량과 원시 최대 용량은 조회에 성공한 경우만 표시하며, macOS 건강도와 별도의 추정치임을 구분한다. 값이 없다고 0이나 정상값으로 대체하지 않는다.

건강도는 하루 단위로 기록하고 배터리 교체 또는 계측 변화가 의심되면 이전 이력과 혼동하지 않게 표시한다. 사용자가 이력을 지울 수 있다. 배터리 전체 수명과 현재 사용 조건에서의 예상 사용 시간을 혼동하지 않는다. 예상 남은 사용 시간은 초기 필수 기능에서 제외한다.

### 온도

해당 기기에서 배터리 센서 값을 읽는 방법과 단위·센서 대상을 검증한다. CPU 온도를 배터리 온도로 대신 표시하지 않는다. 접근 불가·유효하지 않은 값·오래된 값은 명시한다.

과열 방지를 전체 개발 목표에 포함한다. 신뢰할 수 있는 온도와 충전 중지·재개 제어가 모두 확보되어야 활성화한다. 사용자 설정 온도에서 충전을 보류하고, 더 낮은 재개 온도와 충분한 안정 시간을 사용해 빈번한 전환을 피한다. 정확한 기본값은 센서와 제어 검증 단계에서 정한다. Apple의 주변 공기 온도 안내를 배터리 내부 센서의 공식 안전 기준으로 사용하지 않는다. 온도 센서가 없거나 값이 오래되면 자동 제어를 정상 작동으로 표시하지 않는다. 이 기능은 Apple의 하드웨어 보호를 대체하지 않는다.

### 소모가 큰 앱과 프로세스

일정 시간 지속된 CPU 활동 등 실제 확보 가능한 지표로 후보를 보여준다. 첫 구현에서 확보할 수 없는 GPU·에너지 지표는 임의로 생성하지 않는다. CPU 순위만 제공할 경우 CPU 활동 기준임을 명시하고, 정확한 소비 전력이나 배터리 열화 원인이라고 단정하지 않는다.

가능한 경우 앱과 보조 프로세스를 묶고, 상세 보기에서 프로세스명·PID·관측 지표를 확인한다. 데이터가 충분하지 않은 초기 구간은 측정 중으로 표시한다. 계측 방식, 관측 시간, 권한에 따른 한계를 설명할 수 있어야 한다.

일반 프로세스 목록은 사용자가 확인하고 종료하는 방식이다. 사용자의 일반 앱에 대해 정상 종료를 먼저 제공하고, 선택 시에만 강제 종료를 제공한다. 강제 종료 전에 저장하지 않은 작업 손실을 안내한다. 현재 사용자 소유의 종료 가능한 프로세스만 대상으로 하고, 시스템·다른 사용자·로그인 세션 유지에 필요한 프로세스와 앱 자신의 구성 요소는 제외한다. PID 재사용과 대상 변경을 확인한 뒤 동작한다. 애매한 대상은 종료를 허용하지 않는다. 제한된 자동 정리는 아래 바이브 코딩 세션에만 적용한다.

### 충전 상한과 일시 완충

우선 macOS 기본 충전 상한을 활용한다. 외부 앱에서 현재 값을 읽고 변경할 수 있는 접근 경로는 아직 검증하지 않았다. 검증된 직접 제어가 없으면 시스템 배터리 설정으로 이동시키고 설정 방법을 안내한다. 실제 적용을 확인하지 못하면 적용 완료로 표시하지 않는다. 임의로 시스템 설정 파일을 편집하거나 보안 보호를 해제하지 않는다.

한 번만 100% 충전 기능은 macOS의 해당 기능을 호출하거나 사용자에게 안내할 수 있는지 조사한다. 직접 제어와 복귀 동작이 확인된 경우에만 앱 내부 실행 버튼을 제공한다. 이를 위해 별도의 지속 제어가 필요하면 재시작·수면·실패·사용자의 중도 변경까지 복원 규칙을 검증한 뒤 채택한다. 시스템 기능 안내만 가능한 상태를 앱 자체 자동화 완료로 간주하지 않는다.

현재 기기에서 배터리 건강도·프로세스·온도를 보여주는 관찰 버전과, 검증된 충전 제어까지 포함하는 버전을 구분한다. 온도 또는 직접 충전 제어가 확보되지 않으면 해당 원래 요구는 미완료로 보고하고, 제약과 가능한 대안을 설명한다.

### 항해 모드와 교정

항해 모드는 상한에서 충전을 멈추고 자연스럽게 하한 아래로 내려간 뒤 재충전하는 기능이다. 직접 제어가 가능할 때의 제안값은 상한 80%, 재충전 하한 75%이며 사용자가 바꿀 수 있다. 하한에 도달시키기 위한 주기적인 어댑터 차단은 하지 않는다. 시스템이 제공하는 고정 범위만 사용할 수 있으면 그 제한을 표시하고 임의 범위 지원으로 표현하지 않는다.

교정은 잔량 추정의 보정을 위한 사용자 선택 기능으로 포함한다. 배터리의 화학적 열화를 되돌리는 기능으로 홍보하지 않는다. 기본 정기 실행은 끈다. 실제로 필요한 충전·방전 단계, 종료 조건, 전원 분리 시 취소와 복구를 검증한 후 제공한다. 교정 중에도 앱의 온도 보호를 유지한다. 안전한 제어 경로가 확보되기 전에는 자동 교정 버튼을 활성화하지 않는다.

### 에너지 모드와 기존 첨부 기능

배터리와 어댑터 사용 시의 에너지 모드는 시스템이 지원하는 항목 중에서 사용자가 선택한다. 변경과 복원 경로를 검증한 뒤 직접 제어한다. 백그라운드 수집, 프로세스 포함 여부, 메뉴바 표시·팝오버·모양·시작 시 실행은 사용자가 설정할 수 있는 목표 기능이다.

일정과 단축어는 검증된 기능을 호출하는 후속 단계로 포함한다. 수면 중 정확한 시각에 실행된다고 보장하지 않으며 놓친 작업의 처리 규칙을 명시한다. 수면 중 충전 유지, 자동 방전, MagSafe LED, 원시 배터리 비율, 상세 전력 흐름·어댑터 정보는 하드웨어와 OS 접근 경로별로 검증하는 조건부 목표다. 자동 방전은 제공하더라도 기본으로 끄며 명시적으로 선택한 동작에서만 사용한다. 첨부 기능을 목표에서 삭제하지 않지만 미지원 항목을 작동하는 것처럼 표시하지 않는다.

## 5. 바이브 코딩 모드

### 작업의 단위

iTerm2와 Ghostty의 특정 창이나 탭을 자동으로 해석하는 방식에 의존하지 않는다. 터미널에서 앱이 제공하는 실행 도구를 통해 명령을 시작하고, 그 실행을 하나의 관리 세션으로 등록하는 방식을 우선 구현한다. 기존 실행 중인 작업은 사용자가 선택해 관찰할 수 있으나, 실행 이력을 확보하지 못한 프로세스를 소급하여 자동 정리 소유 대상으로 삼지 않는다.

세션에 등록한 명령의 시작·종료와 작업 전용 자원을 추적한다. Claude·Codex 도구별 완료·대기 상태 연동은 실제 설치 버전의 공식 지원 경로를 확인한 뒤 추가한다. API 키나 전체 대화 기록을 받아 작업 완료를 추정하지 않는다.

대화형 CLI가 한 답변을 마치고 입력을 기다리는 것은 전체 세션 종료와 다르다. 최초 지원의 확실한 작업 종료는 등록된 명령의 실제 종료를 확인한 경우다. CPU 사용량 감소나 출력 중단만으로 완료를 판단하지 않는다. 도구가 대기 상태를 명확히 제공하면 대기로 표시하되 자동으로 전체 세션을 정리하지 않는다.

사용자의 '보호 종료'와 '작업 취소'를 구분한다. 보호 종료는 관리와 해당 세션의 잠자기 방지만 해제하며 실행 중인 명령·프로세스에 종료 신호를 보내거나 자동 정리를 시작하지 않는다. 작업 취소는 별도의 명시적 동작으로, 등록된 작업에 정상 취소를 요청하고 실제 명령 종료를 확인할 때까지 취소 중으로 유지한다. 기본 정책에서는 정상 성공 종료 후에만 허용된 자동 정리를 수행한다. 실패·사용자 취소는 조사에 필요한 자원을 보존하고 후보만 표시한다. 사용자가 미리 실패·취소 후 정리 규칙을 지정한 경우에만 실제 명령 종료 확인 이후 그 규칙을 적용한다. 보호 종료·시간 만료·앱 중단 자체는 정리 근거가 아니다. 이름이 모호한 공용 '세션 종료' 동작을 만들지 않는다.

### 화면과 잠자기

사용자가 바이브 코딩 모드를 시작하면 선택한 작업의 실행을 유지하면서 디스플레이 잠자기를 요청한다. 화면 밝기를 0으로 바꾸거나 검은 창을 덮는 것으로 대체하지 않는다. 키보드·마우스로 화면을 켜면 사용자 의도를 존중하고 즉시 다시 끄지 않는다. 내장·외장 화면 조합에서 적용 범위를 시험한다.

작업별로 유휴 상태의 시스템 잠자기를 막는 제한된 전원 관리 요청을 유지한다. 모든 모드에서 영구적으로 시스템 잠자기를 끄는 설정은 사용하지 않는다. 첫 사용 시 사용자가 유지 시간을 선택하며 제안값은 4시간이다. 선택한 시간이 끝나면 사전 알림 후 앱이 소유한 잠자기 방지를 해제한다. 실행 중인 명령을 자동 종료하지 않지만 이후 시스템이 잠들어 작업이 중단될 수 있음을 시작 시 분명히 알린다. 자동 정리를 실행하는 근거로 시간 만료를 사용하지 않는다.

여러 세션이 겹치면 마지막 유효 세션이 끝날 때만 앱 전체의 잠자기 방지 상태를 해제한다. 세션 종료·만료·앱 중단 시 해당 요청을 정리하고, 재시작 후에는 사용자의 선택 없이 과거 세션의 잠자기 방지를 재활성화하지 않는다.

기본 실행 조건은 어댑터 연결·덮개 열림이다. 전원이 분리되면 알리고 기본 정책상 앱의 잠자기 방지를 해제한다. 사용자는 배터리에서도 유지를 선택할 수 있으나 저전력·저잔량 상황의 OS 보호를 우회하지 않는다. 덮개 닫기와 사용자의 직접 잠자기를 무조건 막지 않는다. 기존 화면 잠금 정책을 해제하지 않는다.

첫 검증은 명령줄 빌드·테스트·코딩 작업으로 한다. 화면 캡처와 마우스 조작이 필요한 작업은 화면 꺼짐·잠금 호환성을 확인하기 전에는 지원 완료로 표시하지 않는다. 시스템이 깨어 있어도 외부 프로그램 자체의 일시 중지나 인증·네트워크 대기까지 해결할 수 있다고 보장하지 않는다.

### 정리 정책

세 가지 정책을 제공한다. 초기 기본값은 관찰이다. 안전 자동 정리는 사용자가 활성화하면 이후 매번 확인 없이 사전 허용한 범위에서 동작한다. 고급 규칙은 사용자가 명시한 프로젝트·도구별 범위에 한정한다.

1. 관찰: 정리 후보와 근거를 표시하며 종료하지 않는다.
2. 안전 자동 정리: 완료된 세션에 속하는 것으로 검증되고 사전에 허용된 작업 전용 임시 프로세스만 정상 종료한다.
3. 사용자 규칙: 별도로 지정한 실행 유형에 유예 시간·정리 시점·보존 예외를 적용한다. 프로세스 이름만으로 전역 종료하는 규칙은 제공하지 않는다.

세션 생성 뒤 나타난 프로세스라는 이유만으로 소유권을 인정하지 않는다. 실행 계보·시작 시각·사용자·세션 또는 자원 등록 정보를 조합한다. 부모 종료 후 재부모화되거나 추적을 벗어난 프로세스는 추측해서 정리하지 않는다. PID 재사용을 종료 직전에 재확인한다. 별도 사용자나 root 프로세스의 종료를 위해 권한을 올리지 않는다.

실행 중인 빌드·모델 추론·네트워크 대기 작업을 낮은 활동량만으로 종료하지 않는다. 여러 세션이 사용하는 자원, 사용자가 보존한 서버, 데이터베이스, 로그인 쉘, 터미널 앱, 무관한 브라우저, 시스템 프로세스는 기본 보호한다. 런타임 이름이 node·python·chrome이라는 사실은 정리 근거가 아니다. 해당 세션 전용으로 만든 임시 서버라도 보존 등록이나 다른 세션의 사용이 확인되면 유지한다. 소유권·공유 여부를 신뢰할 수 없으면 정리 후보로만 남긴다.

정상 종료 요청 후 유예 시간을 주고 종료 결과를 확인한다. 응답하지 않는 프로세스를 자동으로 강제 종료하지 않는다. 사용자의 별도 명시적 강제 종료 동작으로 처리한다. 파일·데이터베이스·프로젝트 폴더 삭제나 메모리 비우기는 포함하지 않는다. 기록에는 세션·프로세스·시각·판단 근거·결과를 남기며 작업 메모리가 복구 가능하다고 표현하지 않는다.

실제 명령 종료 이벤트에서 위 성공·실패·취소 정책에 따라 정리하고, 관리 세션이 있을 때만 낮은 빈도의 보완 점검을 수행한다. 후보가 없으면 지속적으로 전체 프로세스를 훑지 않는다. 최초 주기 제안은 60초이며 전력 측정에 따라 조정한다. 이벤트 기반 소유권 수집과 주기적인 활동량 관찰을 구분한다.

### 세션 결과

종료 시 실행 시간, 완료·실패·중단 상태, 정리 결과, 배터리 상태 변화를 제공한다. 화면이 꺼져 있던 시간은 관측한 경우만 표시한다. 실제 계측 없이 절약한 전력량이나 늘어난 배터리 수명을 계산하지 않는다. 알림은 기본적으로 이 맥의 로컬 알림만 사용한다.

## 6. 기술·오픈소스·배포 방향 — 설계자 판단

macOS 네이티브 앱으로 개발한다. 화면은 SwiftUI와 필요한 AppKit으로 만들고, 데이터 읽기는 시스템 전원 정보와 프로세스 정보를 우선 사용한다. 단순 정보 조회에 관리자 권한을 요구하지 않는다. 추가 권한이 필요한 기능은 필요성과 구현 경로가 확인된 뒤 분리한다.

오픈소스 프로젝트를 통째로 채택하기 전에 특정 커밋의 코드, 라이선스, 의존성, 현재 OS 지원, 권한 요구, 중단 시 동작을 검토한다. 단순히 공개된 저장소라는 이유로 재사용하지 않는다. GPL 계열 공개 배포도 허용하는 방향으로 설계하되 정확한 프로젝트 라이선스는 채택할 의존성을 확인한 뒤 정한다. 라이선스가 불명확하거나 서로 맞지 않는 코드는 포함하지 않는다. 재사용한 코드의 출처와 고지, 필요한 소스를 배포물에 포함한다.

참고 후보:

- OpenDente: AlDente와 유사한 기능을 가진 공개 앱. 제작자 검증 범위는 M4 + macOS 26이며 macOS 27 동작은 미확인. 온도 조회와 권한 분리 구현을 검토할 수 있으나 그대로 동작한다고 가정하지 않는다.
- batt: 최신 펌웨어 제한을 설명한다. 일부 환경의 adapter mode는 어댑터 전원을 끊고 다시 연결한다. 사용자의 배터리 사용 최소화 목표에 맞지 않아 기본 충전 엔진으로 채택하지 않는다.
- Stats 등 계측 프로젝트: 필요하면 배터리·센서·프로세스 조회 구현의 후보로 검토한다. 아직 코드 채택 결정은 없다.

첫 단계의 배포는 본인 맥에서 실행하는 로컬 앱이다. 공개 저장소 생성, 외부 업로드, 앱 서명·공증과 일반 사용자용 배포는 별도 단계로 진행한다. 무료 제공 의도는 공개 저장소에 즉시 게시하라는 지시로 해석하지 않는다. 공개 배포 준비 시 개발자 서명·공증과 관련 비용을 확인한다.

## 7. 개인정보와 앱 자체 전력 사용

배터리 이력과 설정은 기본적으로 기기에만 저장한다. 계정, 광고, 분석 전송, 서버를 첫 버전에 넣지 않는다. 프로세스 목록은 기본적으로 메모리에만 유지한다. 관리 세션과 정리 기록에는 필요한 최소 메타데이터만 저장하고 사용자가 삭제할 수 있게 한다. 터미널 출력·명령줄의 비밀값·AI 대화·전체 환경변수는 기록하지 않는다. 영속화가 필요한 식별 정보의 보존 기간은 30일을 제안한다.

전원 변경 이벤트를 우선 사용하고 화면이 보일 때만 전체 프로세스 측정을 강화한다. 초기 제안은 표시 중 프로세스 갱신 5초, 배터리 상태 갱신 30초이며 실제 측정 후 조정한다. 화면을 닫으면 전체 프로세스 순위 수집을 중지하되 활성 관리 세션의 종료·소유권 추적은 유지한다. 백그라운드 애니메이션과 지속적인 외부 명령 실행을 피한다. 온도 이력은 가능할 때 분 단위로 최대 7일, 건강도 이력은 하루 단위로 최대 1년 저장하는 것을 제안한다.

유휴 상태·대시보드 표시·바이브 코딩 모드에서 CPU 활동과 깨우기 빈도를 측정하여 앱 자체 부담을 보고한다. 측정 결과가 목표에 맞지 않으면 갱신 주기와 수집 범위를 줄인다. 잠자기 방지는 사용자가 시작한 관리 세션에만 적용한다.

## 8. 검증 순서와 완료 기준

1. 읽기 전용 기술 검증: 건강도·충전 상태·온도·프로세스 데이터의 실제 제공 여부와 단위를 확인한다. 확인 불가 항목은 기록한다.
2. 충전 제어 경로 검증: 기본 설정 접근, 실제 적용 확인, 일시 완충, 수면·재시작 시 동작을 분리해 조사한다. 다른 충전 관리 앱이 실행 중인지 확인하고 복수 제어의 영향을 배제한다. 기존 앱을 임의 삭제하거나 중지하지 않는다.
3. 관찰 기능 구현: 실제 데이터만 표시하고 누락·오류·권한 제한을 처리한다. 건강도 값은 macOS 시스템 정보와 비교한다.
4. 종료 기능 검증: 버려도 되는 테스트 앱·프로세스로 정상 종료, 거절, 응답 없음, 강제 종료, 대상 변경을 확인한다. 사용자의 작업 앱을 테스트 대상으로 종료하지 않는다.
5. 충전 기능 검증: 제어가 가능한 경우 기존 상태를 기록하고 적용·충전 상태·실제 전력 흐름·복구를 확인한다. 상한 근처 동작은 자연스럽게 해당 잔량에 도달했을 때 검증하며 시험을 위한 반복 완충·방전을 하지 않는다. 즉시 확인할 수 없는 장시간 검증은 남은 항목으로 명시한다.
6. iTerm2와 Ghostty에서 테스트용 명령을 실행하여 화면을 끈 동안 진행 여부, 정상·오류 종료, 시간 만료, 전원 분리, 사용자 복귀, 앱 중단, 복수 세션 겹침을 검증한다. 실제 사용 중인 AI 작업을 시험 대상으로 종료하지 않는다.
7. 테스트용 임시 서버와 보존 서버를 함께 실행해 완료 세션의 허용된 대상만 정리되는지 검증한다. 공유 자원·PID 재사용·추적 실패·입력 대기·권한 거부·정상 종료 무응답에서는 보호 동작을 검증한다.
8. 도구별 완료·대기 신호가 지원되는지 검증한다. 지원되지 않으면 명령 종료 기반임을 표시하고 AI 답변 완료를 안다고 주장하지 않는다.
9. 자체 소비 전력 및 수면 복귀를 확인한다. 검증된 기능과 미검증 기능을 구분해 전달한다.

## 9. 단계 구분과 제외 항목

1단계는 실기 읽기·제어 경로 조사와 배터리 관찰, 2단계는 터미널 세션의 화면 끄기·작업 유지·정리, 3단계는 검증 가능한 충전 제어·항해·과열 방지·일시 완충·선택 교정, 4단계는 일정·단축어·표시 사용자 설정과 기타 하드웨어 기능이다. 조건부 기능은 의도적으로 후순위 검증하지만 요청에서 삭제하지 않는다. 작은 단계 완료를 전체 기능 완성으로 보고하지 않는다.

모든 맥북 지원 보장, 정확한 잔여 수명 예측, 보안 기능 해제, 출처 불명 프로세스의 무인 종료, 사용자 파일 자동 삭제, 클라우드 서비스, 휴대폰 원격 제어는 현재 범위에서 제외한다. 주기적인 강제 방전과 교정을 기본 활성화하지 않는다. 일반적인 메모리 정리 프로그램을 목표로 하지 않는다.

앱 이름, 아이콘, 구체적인 화면 배치와 색상은 아직 정하지 않았다. 이 문서는 기능과 동작을 정하며 시각 디자인은 별도로 결정한다. 내부 데이터 저장 형식과 읽기 모듈의 세부 구조는 구현자가 정할 수 있다.
