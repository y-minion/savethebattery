# 건강 인사이트와 수명 분석 설계

작성일: 2026-10-20 · 하위 프로젝트 1 (A 건강 인사이트 + 사용 패턴 기반 수명 분석)

## 목적

사용자의 충전 습관이 배터리 수명에 어떤 영향을 주는지 실제 측정값으로 보여주고, 수명을 늘리는 행동(충전 상한, 과열 보류, 잠자기 소모 점검)으로 이어지게 한다. AlDente Pro에 없는 분석 기능으로 대체 앱의 가치를 높인다.

성공 기준:
- 첫날부터 현재 상태(건강도, 사이클/설계 사이클, 80%까지 여유)를 보여준다.
- 기간 예측(건강도 80% 도달 시기)은 실측 추세가 충분할 때만, 범위로만 보여준다.
- 패턴 모델은 상대 비교만 보여주고 연수로 환산하지 않는다.
- 모든 데이터는 이 맥에만 저장되고 삭제할 수 있다. 공개 저장소에 실측값을 넣지 않는다.

## 기기 사실 (읽기 전용 확인)

- IORegistry `AppleSmartBattery`: 최상위 `Serial`(문자열), `CycleCount`, `DesignCycleCount9C`; `BatteryData` 아래 `DesignCapacity`, `NominalChargeCapacity`. `LifetimeData`는 없다.
- 앱은 30초마다 측정한다(`AppModel.refresh`). 기존 `history.json`은 60초 간격 샘플 7일 보관.
- 개인 기기 값은 이 문서와 저장소에 기록하지 않는다.

## 범위

포함:
1. 스냅샷 확장: `healthPrecise`(0.1% 해상도), `designCapacity`, `designCycles`, `batteryID`(일련번호 SHA-256 앞 16자리 hex, 원본 미저장).
2. 하루 기록(최대 400일): 측정 시간, 어댑터 시간, 잔량 ≥90%/≥95% 시간, 온도 ≥35°C/≥40°C 시간, 최고 온도, 평균 잔량, 스트레스 적분(현재 패턴, 상한 80% 가정), 그날 마지막 건강도·사이클·배터리 식별값.
3. 잠자기 기록(최근 30회).
4. 분석: 현재 상태, 수명 추세(Theil–Sen, 날짜·사이클), 상대 스트레스 지수와 상한 80% 비교, 규칙 기반 제안(최대 3개).
5. 앱 "건강 분석" 화면, 대시보드 한 줄 요약, `vbctl health [--json]`.

제외: 연수 환산, 셀 모델 보정, 클라우드 동기화, 알림(하위 프로젝트 2), 단축어·일정(하위 프로젝트 3).

## 구조

- `BatteryCore` (순수 함수, 테스트 대상)
  - `BatterySnapshot` 확장 필드와 디코딩.
  - `StressModel`: 잔량·온도 → 상대 스트레스율.
  - `DailyUsage`, `HealthLedger.record`: 연속된 두 샘플 사이 구간을 하루 기록에 누적.
  - `BatterySegment.current`: 배터리 교체 이후 구간만 추림.
  - `HealthTrend`: Theil–Sen 추세와 80% 도달 범위.
  - `SleepEvent`, `HealthAdvisor`, `HealthReport`.
- `BatteryPlatform`
  - `JSONFile`: 손상 파일을 `.corrupt`로 옮기고 빈 값으로 시작, 0600 권한, 원자적 쓰기.
  - `HealthStore`(`health.json`: 마지막 샘플 + 하루 기록), `SleepStore`(`sleep.json`).
  - `HealthRecorder`: 하루 기록을 메모리에 누적하고 5분마다, 그리고 잠들기 직전과 앱 종료 시 저장한다(30초마다 1년치 파일을 다시 쓰지 않기 위해). 앱이 강제 종료되면 최대 5분이 "모름"이 된다.
- 앱: 수집 연결, `NSWorkspace` 잠자기/깨어남 관찰, `HealthView`, 사이드바, 대시보드 요약, 설정 문구.
- CLI: `vbctl health [--json]`은 기록을 읽기만 한다.

## 규칙

### 누적
- 구간 상태는 앞 샘플 값으로 본다(왼쪽 점 규칙).
- 간격이 0 이하이거나 300초를 넘으면 그 구간은 "모름"으로 누적하지 않는다(잠자기, 앱 종료 포함). 시계가 거꾸로 가면 버린다.
- 구간이 로컬 자정을 넘으면 날짜별로 나눈다.
- 잔량이 없으면 잔량 관련 시간을, 온도가 없으면 온도 관련 시간을 누적하지 않는다. 스트레스는 둘 다 있을 때만 누적하고 `stressSeconds`에 그 시간을 더한다.
- 구간 누적과 별개로, 샘플마다 그날의 건강도·사이클·설계 용량·배터리 식별값을 마지막 값으로 갱신한다.
- 400일보다 오래된 날은 지운다.
- 이력 기록 설정(`backgroundHistory`)이 꺼져 있으면 하루 기록과 잠자기 기록 모두 수집하지 않는다.

### 배터리 교체 감지
최신 날부터 거꾸로 보며, 인접한 두 날 사이에 다음 중 하나가 있으면 그 지점에서 자른다: 식별값이 둘 다 있고 다름, 설계 용량이 둘 다 있고 다름, 사이클 수가 감소함. 추세는 잘린 이후 구간만 쓴다.

### 스트레스 모델
- 근거: [BU-808 Table 3](https://batteryuniversity.com/article/bu-808-how-to-prolong-lithium-based-batteries) 1년 보관 후 용량 손실(%): 0°C 40%→2, 100%→6; 25°C 40%→4, 100%→20; 40°C 40%→15, 100%→35. 참고: [VTT](https://cris.vtt.fi/en/publications/aging-and-degradation-of-lithium-ion-batteries/), [IEST](https://iestbattery.com/gas-generation-during-high-t-storage-at-varied-soc/).
- 각 온도에서 잔량 40~100%는 선형 보간, 40% 미만은 40% 값, 100% 초과는 100% 값.
- 온도 사이는 손실의 로그를 선형 보간. 40°C 초과는 25→40°C 기울기로 외삽. 온도는 0~60°C로 제한.
- 정규화: 25°C·잔량 40% = 1.0. (예: 25°C·100% = 5.0, 25°C·80% ≈ 3.67)
- 상한 80% 가정: 잔량을 `min(잔량, 80)`으로 바꿔 같은 기록을 다시 적분한다. 실제로는 충전 패턴이 달라지므로 근사치임을 표시한다.
- 표시: 평균 스트레스(적분 / `stressSeconds`), 상한 80% 감소율 = 1 − (가정 적분 / 실제 적분). 이미 감소가 0.5% 미만이면 "이미 80% 이하로 유지 중".
- 화면 문구에 "일반 리튬이온 연구 기반 · 이 배터리에서 검증된 값 아님"을 붙인다.

### 수명 추세
- 입력: 현재 구간의 건강도가 있는 날. x = 첫날로부터의 일수.
- 조건: 첫날~마지막 날 30일 이상, 건강도가 있는 날 5개 이상, 최대−최소 1.0%p 이상. 미충족 시 `collecting(days, points)`.
- 마지막 건강도가 80 이하면 `alreadyBelow`.
- Theil–Sen: 모든 쌍 기울기의 중앙값을 기울기로, `중앙값(y − 기울기·x)`를 절편으로. 범위는 쌍 기울기의 25번째·75번째 백분위수로 같은 계산을 한다(가파른 기울기 → 이른 날짜).
- 중앙 기울기가 0 이상이면 `notDeclining`. 범위 경계 기울기가 0 이상이면 그 경계는 "알 수 없음"(nil).
- 예측 날짜가 15년을 넘으면 "15년 이상"(nil)으로 둔다. 과거 날짜로 계산되면 오늘로 맞춘다.
- 사이클 추세: 같은 방식으로 x = 사이클. 서로 다른 사이클 값 5개 이상, 사이클 폭 10 이상일 때만 80% 도달 사이클 범위를 낸다.

### 잠자기 소모
- 잠들기 직전 스냅샷과 깬 직후 스냅샷으로 기록한다. 둘 중 하나라도 어댑터 연결이면 소모를 계산하지 않는다.
- 1시간 미만 잠자기는 계산하지 않는다(잔량이 정수라 짧은 잠은 1%만 줄어도 과장된다). 잔량이 늘었으면 계산하지 않는다.
- 시간당 소모 1.0%를 넘으면 강조한다. 최근 30회 보관.

### 제안 (최대 3개, 이 순서)
1. 최근 7일 잔량 ≥95% 시간이 6시간 이상이고 충전 상한이 꺼져 있거나 80% 초과 → "상한 80% 권장" (대시보드로 이동).
2. 최근 7일 온도 ≥35°C 시간이 2시간 이상이고 과열 보류가 꺼져 있음 → "과열 보류 켜기 권장" (설정으로 이동).
3. 최근 5회 잠자기 중 시간당 1.0% 초과가 있음 → "잠자기를 막는 앱 확인" (앱과 프로세스로 이동).

## 오류 처리

- 센서값 없음: 해당 시간 "모름".
- 저장 파일 손상: `<이름>.corrupt`로 옮기고 새로 시작. 앱 메시지로 알리지 않고 다음 저장에서 복구.
- 쓰기 실패: 앱 메시지로 알린다(기존 이력과 동일).
- 배터리 정보 없음(데스크톱·CI): 화면과 CLI는 "배터리 정보 없음"을 보여주고 CLI는 0으로 종료.

## 화면과 CLI

- 사이드바 "건강 분석": 현재 상태, 수명 추세, 충전 습관(7일·30일), 잠자기 소모, 제안, 기록 삭제.
- 대시보드: "건강 분석 · <추세 상태 요약>" 한 줄과 이동 버튼.
- 설정: 이력 토글 문구를 "배터리 이력 기록 (잔량 7일 · 건강 분석 1년)"으로.
- `vbctl health`: 사람이 읽는 요약. `--json`: `HealthReport` JSON(하위 프로젝트 3의 단축어가 사용).

## 검증

- 단위 테스트: 스냅샷 새 필드와 기존 이력 호환, 스트레스 표 재현과 단조성, 누적(공백, 자정 분할, 시계 역행, 결측), 400일 보관, 교체 감지, 추세(수집 중, 하락 없음, 이상치, 80% 이하, 범위 순서), 사이클 추세 조건, 잠자기 계산(어댑터, 짧은 잠, 잔량 증가), 제안 경계값, 저장소 손상 복구와 보관 한도, 보고서 구성.
- 기기 확인: `vbctl health`가 실행되고, 앱 화면이 열리며, 실측 하루 기록이 쌓이는지 확인한다. 개인 값은 공개 문서에 남기지 않는다.
- 한계: 추세 예측은 30일 이상 사용 후에만 검증 가능하다.
