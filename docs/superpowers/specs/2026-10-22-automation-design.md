# 자동화 설계: 충전 일정, 명령줄 충전 제어, 단축어

작성일: 2026-10-22 · 하위 프로젝트 3-2 (전체 순서: 3-1 Xcode 전환 → **3-2 자동화** → 3-3 Pro 기능 무료화 → 3-4 배포)

## 의도와 이유

VibeBattery는 모든 사람에게 무료로 배포할 맥북 배터리·전원 도우미다. 사용자는 AlDente Pro처럼 다른 앱이 유료로 파는 기능을 모두 무료로 제공하는 것을 차별점으로 정했다. 이 문서는 그중 자동화 묶음을 다룬다.

- AlDente Pro의 Schedule, Automatic Catch Up, Shortcuts에 해당한다.
- macOS 26.4+ 단축어에는 "배터리 충전 상한 설정" 동작과 시간 기반 자동화가 있지만, 80~100%만 쓸 수 있고 한 번 완충 예약은 없다. VibeBattery는 50~100%와 완충까지 다룬다.

사용자가 특히 강조한 점: **기능이 많아져도 혼란스럽지 않고 쉽게 쓸 수 있어야 한다.** 그래서 이 문서는 기능 규칙과 함께 화면 구성 원칙(앞으로 추가될 기능에도 적용)을 정한다.

## 목표

1. **충전 일정**: 요일과 시각을 정해 상한 바꾸기, 한 번 완충 시작, 상한 끄기를 자동으로 실행한다. 맥이 잠들었거나 앱이 꺼져 있어 놓친 일정은 다음에 앱이 깨어 있을 때 실행한다(일정 따라잡기).
2. **명령줄 충전 제어**: `vbctl charge set|off|topup|end|status`. 단축어의 "셸 스크립트 실행"과 터미널에서 쓸 수 있다.
3. **단축어 전용 동작**(App Intents): 충전 상한 설정, 한 번 완충 시작, 완충 종료, 상한 끄기, 배터리 상태 가져오기. Xcode 전환(3-1)이 끝나야 만들 수 있다.
4. **"왜 바뀌었지?"에 답하는 화면**: 상한이 자동으로 바뀌면 언제, 무엇 때문에 바뀌었는지 항상 보인다.

## 하지 않는 것 (비목표)

- 잠든 맥을 깨워 일정을 실행하는 것. 루트 권한의 `pmset schedule`이 필요하다. 놓친 일정은 따라잡기로 처리한다.
- 위치, 실행 중인 앱, Wi-Fi 같은 조건 트리거. 단축어 자동화가 이미 제공하니, 사용자는 3번의 단축어 동작과 조합하면 된다.
- 3-3의 Pro 기능(전력 흐름, 상태 아이콘, 잠자기 중 충전 멈춤 등). 다만 아래 화면 구성은 그 기능들이 들어올 자리를 미리 정한다.
- App Store 배포. 그래서 앱은 샌드박스 없이 Developer ID로 배포하고, Xcode 전환 후에도 `vbctl`은 `Contents/MacOS/vbctl`에 둔다. `~/Library/Application Support/VibeBattery`도 그대로 쓴다.

## 실패로 보는 것 (반목표)

- 사용자가 모르는 사이에 상한이 바뀌고 이유를 찾을 수 없는 상태.
- 같은 설정이 여러 화면에 흩어져 어디서 바꿔야 할지 모르는 상태.
- 일정을 만들려면 설명서를 읽어야 하는 상태.
- 명령줄이나 단축어로 바꾼 상한을 앱이 "다른 곳에서 바뀜"으로 오인해 경고하거나 과열 보류를 멈추는 것.
- 놓친 일정이 한꺼번에 여러 번 실행되는 것. 예: 일주일 꺼져 있다 켜자 완충이 시작되는 것.

## 제약

- 기존 안전 원칙을 유지한다. SMC 쓰기 없음, 다른 충전 관리 앱이 있으면 모든 변경 차단, 모든 쓰기는 다시 읽어 확인.
- 80% 미만 상한은 헬퍼가 쓴다. 헬퍼는 서명 식별자가 `io.github.y-minion.vibebattery`인 `/Applications/VibeBattery.app`의 요청만 받는다(`HelperPolicy`). 따라서 `vbctl`이 헬퍼를 직접 부를 수 없다.
- 충전 기록(`charge.json`: 마지막으로 쓴 값, 쓰기 횟수, 쓰기 기록 20건)은 알림의 "외부 변경" 판단과 과열 보류의 기준이다. 쓰는 주체가 둘이 되면 이 판단이 깨진다.
- 모든 화면 문구는 한국어, 쉬운 말. 내부 용어(MCL, PowerUI, topoff)는 화면에 보이지 않는다.
- 개인 기기 값은 저장소에 넣지 않는다.

## 사용자와 정한 것

- 자동화 4종(일정+따라잡기, 명령줄, 단축어, 그리고 3-3으로 넘긴 Pro 기능들)을 무료로 제공한다.
- 단축어 전용 동작을 위해 Xcode로 빌드한다(3-1). 사용자가 Xcode를 설치한다.
- 쉽게 쓸 수 있어야 한다.

## 구조 결정 (작성자 판단, 근거 포함)

### 충전 설정을 쓰는 주체는 앱 하나

일정, 명령줄, 단축어의 모든 충전 변경은 **실행 중인 앱의 `ChargeController.apply`를 거친다.**

근거:
- 헬퍼가 앱만 받아들인다.
- 충전 기록의 주체가 하나여야 "외부 변경" 판단이 맞는다.
- 쓰기 기록에 요청한 쪽이 남는다.

- 쓰기 기록의 출처(`ChargeWrite.Source`)에 `schedule`, `cli`, `shortcut`을 추가한다.
- 앱이 실행 중이 아니면 `vbctl charge set` 등은 "VibeBattery 앱이 실행 중이어야 합니다. 앱을 열고 다시 시도하세요."를 내고 종료 코드 3으로 끝난다. `vbctl charge status`는 지금처럼 앱 없이 읽기만 한다.
- 단축어 동작은 앱 프로세스 안에서 실행된다. App Intents가 앱을 백그라운드로 띄운다.

### 명령줄 ↔ 앱 통신

- 같은 사용자만 접근하는 로컬 통로를 쓴다. 제안: `~/Library/Application Support/VibeBattery/control.sock` Unix 도메인 소켓, 0600 권한, 연결 시 `getpeereid`로 같은 UID인지 확인.
- 요청은 한 줄 JSON: `{"command":"setLimit","value":70}`. 응답: `{"ok":true,"state":{...},"message":"..."}`.
- 받는 명령은 `setLimit(50…100, 5 단위)`, `clearLimit`, `startTopUp`, `endTopUp`뿐이다. 그 밖의 요청은 거절한다.
- 시간 제한(작성자 판단): 연결과 요청 전송은 5초 안에 끝나야 한다. 실패하면 종료 코드 3을 낸다. 응답은 최대 15초 기다린다. 헬퍼 쓰기와 다시 읽기 확인에 최대 약 7초가 걸리기 때문이다. 응답 대기가 시간을 넘기면 종료 코드 1과 "결과를 확인하지 못했습니다. `vbctl charge status`로 확인하세요"를 낸다. 앱은 받은 요청을 끝까지 처리하고 쓰기 기록에 남긴다.
- 다른 통로를 고르는 것은 구현자에게 맡긴다. 단, 같은 사용자 제한, 정해진 명령만 받기, 위 시간 규칙은 지켜야 한다.
- 일정, 명령줄, 단축어에서 온 변경은 모두 **사용자가 직접 한 변경**으로 취급한다(`byUser:true`, 작성자 판단). 과열 보류 중이면 보류를 끝내고 새 값을 적용한다. 완충 후 복원에 쓰는 "마지막으로 정한 상한"(`lastWritten`)도 갱신한다. 출처만 다르게 기록한다.

### 일정 규칙

- 일정 하나 = 요일 집합(1개 이상) + 시각(시:분, 이 맥의 현지 시간) + 동작(`setLimit(N)` | `startTopUp` | `clearLimit`) + 켜짐/꺼짐 + 이름(자동 생성, 수정 가능). 최대 10개.
- **판단은 순수 함수**: `SchedulePolicy.due(rules, lastCheck, now, calendar) -> Occurrence?`. 마지막 확인 시각 이후 지난 실행 시점 중 **가장 최근 1개만** 돌려준다. 동작끼리는 서로 덮어쓰므로 가장 최근 것만 의미가 있다.
- **따라잡기 창 12시간**(작성자 판단): 놓친 시점이 12시간보다 오래됐으면 실행하지 않고 건너뛴다. 일주일 쉬었다 켜도 엉뚱한 완충이 시작되지 않게 하기 위해서다. 건너뛴 사실은 일정 화면의 "최근 실행"에 남긴다.
- 같은 시각에 두 일정이 있으면 목록에서 아래쪽 일정이 이긴다. 화면은 같은 시각 일정에 경고를 표시한다.
- **시계 문제**: 마지막 확인 시각이 미래면(시계가 되돌아감) 지금으로 맞추고 실행하지 않는다. 일광절약시간처럼 같은 현지 시각이 두 번 오거나 아예 없는 날은 `Calendar`의 다음 일치 시점 규칙을 따르고, 한 번만 실행한다.
- **확인 시점**: 앱 갱신(30초)마다, 깨어날 때, 앱을 켤 때. 실행되는 시각은 예정보다 최대 30초 늦을 수 있다(App Nap 아래에서는 약 2분).
- **수동 변경과의 관계**: 사용자가 직접 바꾸면 다음 일정 시각까지 그 값이 유지된다. 일정은 시각에 한 번 실행되고 계속 강제하지 않는다.
- **과열 보류와의 관계**: 보류 중의 상한 일정은 사용자가 직접 적용한 것과 같이 처리한다(보류를 끝내고 새 값 적용). 보류 중의 완충 일정은 지금 규칙대로 거절되고 실패로 기록된다.
- **한 번 완충 중 일정**(작성자 판단): 일정은 정한 시각에 실행한다. 완충 중에 상한 일정이 오면 완충을 끝내고(`endTopUp`) 일정의 값을 적용한다. 그 값이 새 "마지막으로 정한 상한"이 된다. "상한 끄기" 일정이면 완충을 끝내고 상한을 끈다.
- **새로 만들거나 다시 켠 일정**(작성자 판단): 만든 시각 또는 켠 시각 이후의 실행 시점만 센다. 그 전의 시점은 따라잡지 않는다. 일정은 앱 화면에서만 바꿀 수 있다.
- **실패**: 다른 충전 관리 앱, 헬퍼 없음, 다시 읽은 값 불일치 등. 재시도하지 않는다. 실패는 일정 화면의 "최근 실행"과 알림 "일정 실행 실패"(기본 켜짐)로 알린다. 성공 알림 "일정 실행됨"은 기본 꺼짐이다.
- **저장**: 일정 목록은 `preferences.json`(관용적 디코딩 유지). 마지막 확인 시각과 최근 실행 10건은 `schedule.json`(0600, `JSONFile` 사용).

### 명령줄

```
vbctl charge status [--json]     # 지금처럼, 앱 없이 읽기
vbctl charge set <50-100>        # 5 단위
vbctl charge off
vbctl charge topup
vbctl charge end
```

- 종료 코드:
  - 0: 성공
  - 1: 적용 실패(거절, 확인 불일치, 다른 관리 앱)
  - 2: 사용법 오류
  - 3: 앱이 실행 중이 아님
- 출력은 앱 메시지와 같은 한국어 문장이다. `--json`은 상태 객체를 출력한다.
- `status --json`에 `origin`(VibeBattery·외부·없음), `topUpActive`, `nextSchedule`(앱이 실행 중일 때만)을 추가한다. 기존 키는 유지한다.

### 단축어 동작 (3-1 이후)

- **충전 상한 설정**: 50~100, 5 단위
- **한 번 완충 시작**
- **완충 종료**
- **충전 상한 끄기**
- **배터리 상태 가져오기**: 잔량, 충전 중 여부, 현재 상한, 건강도(추정), 온도를 돌려준다.

동작 이름과 설명은 한국어. 실패하면 앱과 같은 메시지로 단축어 오류를 낸다. Xcode 전환이 늦어지면 이 항목만 뒤로 미루고 나머지는 먼저 낸다.

## 화면 구성 원칙 (이번 작업과 이후 기능 모두에 적용)

1. **한 기능은 한 곳에만.** 설정을 바꾸는 곳은 기능마다 하나다. 대시보드는 상태를 보여 주고, 그 기능의 페이지로 가는 길만 둔다.
2. **기본은 단순하게, 자세한 것은 펼쳐서.** 처음 보이는 것은 지금 상태와 가장 흔한 동작 하나다. 쓰기 기록이나 세부 기준값은 "자세히"를 눌러야 보인다.
3. **모든 자동 변경은 이유를 말한다.** 상한이 바뀐 출처(사용자, 일정 "이름", 단축어, 명령줄, 과열 보류, 완충 후 복원)를 쓰기 기록에서 읽어 "22:00 일정 '밤에는 70%'로 바뀜"처럼 보여 준다.
4. **처음 쓰는 사람에게는 견본을.** 빈 화면 대신 한 번 눌러 추가하는 견본 일정을 보여 준다.
5. **문장으로 읽히게.** 일정 한 줄은 "평일 22:00 · 상한 70%"처럼 읽힌다. 다음 실행 시각("다음: 오늘 22:00")을 함께 보인다.

### 사이드바 (변경)

| 순서 | 항목 | 담는 것 |
|---|---|---|
| 1 | 대시보드 | 상태 요약(잔량, 충전 상태, 현재 상한과 마지막 변경 이유, 다음 일정, 건강 요약). 바꾸는 컨트롤은 없고 각 페이지로 이동 |
| 2 | **충전** (신규) | 현재 상한 조절(지금 대시보드의 충전 제어 카드 이동), 한 번 완충, **일정**, 과열 보류(설정에서 이동), 헬퍼 상태, "자세히: 최근 변경 기록" |
| 3 | 건강 분석 | 지금과 같음 |
| 4 | 바이브 코딩 | 지금과 같음 |
| 5 | 앱과 프로세스 | 지금과 같음 |
| 6 | 설정 | 앱 전체 설정만: 로그인 시 실행, 알림, 이력 기록, 명령줄·단축어 안내 |

3-3의 기능이 들어올 자리:
- 전력 흐름, 하드웨어 잔량 → 대시보드의 상태 카드
- 잠자기 관련 두 기능, 충전기 빼면 완충 복귀, 보정 안내 → 충전 페이지의 "충전 방식" 묶음
- 상태 아이콘 → 메뉴 막대

### 충전 페이지 (위에서 아래로)

1. **지금 상한**: 큰 글씨로 현재 상한과 그 이유 한 줄. 아래에 상한 조절(스테퍼 + 적용, 80% 권장 표시), 상한 끄기, 한 번 100% 충전 / 완충 종료.
2. **일정**:
   - 일정이 없으면 견본 3개를 보여 준다. 누르면 바로 추가되고 이후 수정할 수 있다.
     - "밤에는 70%" — 매일 22:00, 상한 70%
     - "평일 아침 완충" — 월~금 07:00, 한 번 완충
     - "주말엔 80%" — 토·일 00:00, 상한 80%
   - 일정 목록: 한 줄 문장 + 켜짐 토글 + 다음 실행 시각. 누르면 편집 시트가 열린다.
   - 편집 시트는 세 칸이다: 요일(칩, "매일/평일/주말" 빠른 선택), 시각, 동작(상한 N% / 한 번 완충 / 상한 끄기). 이름은 자동으로 채우고 수정할 수 있다. 같은 시각 일정이 있으면 경고를 보인다.
   - "최근 실행": 기본은 접혀 있고 최근 10건(성공, 실패, 건너뜀과 이유)을 보여 준다.
   - 안내 한 줄: "앱이 실행 중일 때 동작합니다. 맥이 잠들어 놓친 일정은 12시간 안이면 깨어날 때 실행합니다."
3. **과열 보류**: 설정에서 옮겨 온 카드. 문구는 유지한다.
4. **헬퍼와 기록**(접힘): 헬퍼 상태와 설치 안내, 최근 충전 변경 기록 20건(시각, 내용, 출처, 결과).

### 메뉴 막대 메뉴

- 지금 줄들에 "상한 70% · 다음 일정 22:00"을 더한다.
- "한 번 100% 충전" / "완충 종료"를 빠른 동작으로 추가한다. 가장 자주 쓰는 동작만 넣고, 상한 조절은 넣지 않는다(실수 방지).

### 설정 → "명령줄과 단축어" 카드

- `vbctl` 경로 복사 버튼과 예시 3줄을 보여 준다.
- "단축어 앱에서 'VibeBattery'를 검색하세요" 안내(3-1 이후)를 넣는다.

## 오류와 경계

- 앱이 꺼져 있을 때 명령줄 요청: 종료 코드 3과 안내 문장.
- 소켓 파일이 남아 있지만 앱이 없으면 연결 실패를 "앱 실행 중 아님"으로 처리한다. 앱이 시작할 때 오래된 소켓을 지우고 새로 만든다.
- 앱 두 개가 동시에 실행되면(드묾) 소켓은 나중에 뜬 쪽이 갖는다. 기존 동작상 두 앱 모두 쓸 수 있으므로 새 문제는 아니다(작성자 판단: 이번 범위에서 막지 않음).
- 일정 실행 중 다른 충전 관리 앱이 감지되면 실패로 기록한다(기존 차단 규칙).
- 일정 목록이 손상되면 기존 관용적 디코딩대로 그 항목만 버리고 나머지를 유지한다.

## 알림 추가

- **일정 실행 실패**(기본 켜짐): "일정 '밤에는 70%' 실행 실패 · 다른 충전 관리 앱이 실행 중입니다" → 누르면 충전 페이지.
- **일정 실행됨**(기본 꺼짐).
- 기존 "상한이 다른 곳에서 바뀜" 판단은 쓰기 횟수 기준이라, 앱을 거친 변경에는 자동으로 울리지 않는다. 이것을 테스트로 고정한다.

## 검증

- 순수 함수 단위 테스트(`SchedulePolicy`):
  - 다음 실행 시각
  - 여러 일정 중 가장 최근 1개
  - 12시간 창 경계(11:59 실행, 12:01 건너뜀)
  - 같은 시각 충돌
  - 시계 역행
  - 꺼진 일정 무시
  - 요일 경계(일요일 23:59 → 월요일)
  - 일광절약시간이 있는 시간대
- 명령줄:
  - 인수 해석, 범위·5 단위 검증, 종료 코드
  - 앱이 없을 때 3
- 통로:
  - 정해진 명령 외 거절
  - 다른 UID 거절(테스트 가능한 범위에서)
  - 5초 시간 제한
- 충전 기록:
  - 일정·명령줄·단축어 출처가 쓰기 기록에 남음
  - 이 변경들이 "외부 변경" 알림을 울리지 않음
- 실기기:
  - 일정 1분 뒤로 만들어 실행 확인
  - 잠자기 중 지난 일정이 깨어날 때 실행
  - `vbctl charge set 70` 실행 시 앱 기록에 출처 `cli`
  - 앱 종료 상태에서 종료 코드 3
  - 단축어 동작(3-1 이후)
- 화면: 충전 페이지와 견본 일정, 편집 시트, 메뉴 막대를 사용자가 직접 본다.

## 구현자에게 맡기는 것

- 명령줄 ↔ 앱 통로의 구체 방식(위 제약 안에서).
- 화면의 세부 레이아웃, 색, 아이콘(위 구성과 원칙 안에서).
- 일정 이름 자동 생성 문구.
- `schedule.json`의 세부 구조.
