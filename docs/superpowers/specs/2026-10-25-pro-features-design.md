# Pro 기능 무료화 설계: 상태 아이콘, 메뉴 막대 창, 전력 흐름, 하드웨어 잔량, 저전력 모드, MagSafe LED

작성일: 2026-10-25 · 하위 프로젝트 3-3 (전체 순서: 3-1 Xcode 전환(완료) → 3-2 자동화(완료) → **3-3 Pro 기능 무료화** → 3-4 배포)

## 의도와 이유

VibeBattery는 누구나 무료로 쓰는 맥북 배터리·전원 도우미다. AlDente는 충전 상한과 수동 방전만 무료로 주고 나머지는 Pro(연 €11.49 또는 평생 €23.99)로 판다. 이 하위 프로젝트는 AlDente에서 넘어온 사람이 "Pro에는 있었는데 여기는 없네"라고 느끼지 않게, 남은 Pro 기능 중 이 맥에서 만들 수 있는 것을 무료로 넣는다.

사용자 본인이 Pro 기능이 필요했던 순간은 없었다. 기준은 개인 필요가 아니라 AlDente Pro 기능 목록이다.

앞 하위 프로젝트에서 사용자가 강조한 원칙은 그대로다: **기능이 많아져도 혼란스럽지 않고 쉽게 쓸 수 있어야 한다.**

## 목표

### 1. 실시간 메뉴 막대 아이콘 (사용자가 시안 A를 고름)

- 배터리 그림(잔량만큼 채움) 안에 상태 기호, 오른쪽에 잔량 숫자 `70%`.
- 상태는 넷이다:

| 상태 | 판단 | 기호 |
|---|---|---|
| 충전 중 | `charging == true` | 번개 |
| 상한에서 멈춤 | 충전기 연결 `onAC` 이고 충전 안 함 | 플러그 |
| 배터리 사용 | 충전기 없음 | 기호 없음 |
| 과열로 충전 보류 | 과열 보류가 상한을 낮춘 상태(`heatHolding`) | 온도계, 주황색 |

  과열 보류는 다른 상태보다 앞선다.
- 설정에서 모양을 셋 중에 고른다: **아이콘 + 잔량**(기본), **아이콘만**, **잔량만**(숫자 앞에 작은 상태 기호; 배터리 사용 중이면 기호 없음).
- 아이콘은 밝은/어두운 메뉴 막대 모두에서 읽혀야 한다. 과열 보류의 주황색 외에는 시스템 메뉴 막대 색을 따른다.

### 2. 메뉴 막대 창 (팝업 꾸미기)

지금의 글자 메뉴(`MenuBarExtra` 기본 메뉴)를 작은 창으로 바꾼다. 창은 항목(구역)들의 세로 목록이고, 항목마다 보이기/숨기기와 순서를 설정에서 바꾼다.

| 항목 | 내용 | 처음 상태 (사용자가 고름) |
|---|---|---|
| ① 잔량과 상태 | 큰 잔량 숫자, 상태 한 줄: 상한·충전 상태·온도 (예: "상한 80%에서 멈춤 · 충전기 연결 · 31.5°C") | 보임 |
| ② 전력 흐름 | 목표 3의 막대 (작은 크기) | 보임 |
| ③ 충전 상한 바로 바꾸기 | 단추 60·70·80·90·100·끄기. 누르면 바로 적용 | 보임 |
| ④ 한 번 완충과 다음 일정 | "한 번 100% 충전"/"완충 종료" 단추, 다음 일정 한 줄 | **숨김** |
| ⑤ 저전력 모드 | 스위치 (목표 5) | 보임 |
| ⑥ 배터리 정보 | 하드웨어 잔량, 건강도(추정), 사이클 | 보임 |
| ⑦ 바이브 코딩 작업 | 실행 중인 터미널 작업 수, 대표 작업 한 줄(명령 이름 · 잠자기 방지 여부 · 경과 시간). 없으면 "실행 중인 작업 없음" | 보임 |

- 창 아래쪽 줄은 항상 보인다: 대시보드 열기, 명령 복사(Claude/Codex), 앱 종료. 지금 메뉴의 "배터리 설정 열기"는 대시보드와 ⑤의 대체 문구로 옮긴다.
- ③의 쓰기는 기존 앱 쓰기와 같은 경로(`AppModel.applyCharge`, 출처 `user`)를 쓴다. 쓰기가 막힌 경우(다른 충전 관리 앱, 지원 안 함)에는 단추를 비활성화하고 이유를 한 줄로 보인다. 헬퍼가 없으면 60·70은 비활성화하고 "80% 미만은 헬퍼가 필요합니다"를 보인다. 현재 상한이 단추에 없는 값(예: 75%)이면 어느 단추도 강조하지 않고 ①의 상태 줄에 실제 값이 보인다.
- 알림 클릭으로 창을 다시 여는 기존 동작(`MenuLabel`에서 `openMain` 연결)은 유지한다.
- 설정 화면에 "메뉴 막대" 카드를 새로 둔다: 아이콘 모양 선택, 항목 목록(보이기 스위치, 위/아래 이동), "기본값으로 되돌리기".
- 설정은 기존 `UserPreferences`에 저장한다. 이전 파일이나 모르는 항목 이름이 섞인 파일을 읽어도 다른 설정을 잃지 않는다(기존 lossy 디코딩 관례). 새 버전에서 항목이 추가되면, 저장된 순서 뒤에 기본 상태로 붙는다.

### 3. 전력 흐름 (사용자가 시안 B, 막대를 고름)

- 한 줄 요약: "충전기에서 32 W 들어옴" + 어댑터 이름(예: "70W USB-C").
- 막대: 들어오는 전력을 "맥 18 W"(초록)와 "배터리 +14 W"(파랑)로 나눈다. 범례 한 줄.
- 상태별:
  - 충전 중: 위와 같다.
  - 상한에서 멈춤: 충전기 → 맥만 (막대 전체가 맥).
  - 배터리 사용: "배터리에서 N W 사용" 한 줄과 막대 전체가 배터리(주황 계열).
  - 충전기 연결 중인데 배터리도 쓰는 경우(macOS가 상한까지 내리는 중, 또는 어댑터 출력 부족): 충전기 → 맥과 배터리 → 맥을 함께 보인다.
- 대시보드에 카드로, 메뉴 막대 창 ②에 작게 같은 내용을 쓴다.
- 값은 `AppleSmartBattery`의 `PowerTelemetryData`(`SystemPowerIn`, `SystemLoad`, `BatteryPower`, mW 단위로 보임)와 `AdapterDetails`(`Watts`, `Name`)에서 읽는다. 2026-10-25 이 맥에서 읽힘: 70W USB-C, `SystemPowerIn` 8754, `SystemLoad` 8754, `BatteryPower` 0 (상한에서 멈춤). 배터리 쪽 값과 부호는 기존 `BatterySnapshot.watts`(전압 × 전류)와 맞춰 보고, 어느 값을 쓸지는 실기기에서 충전 중·배터리 사용 중을 각각 확인해 정한다(빌더 판단).
- 키가 없으면(다른 모델, 데스크톱, CI) 카드는 "이 맥에서는 전력 흐름을 읽을 수 없습니다"를 보이고, 메뉴 막대 창 ②는 숨는다. 추정해서 채우지 않는다.
- 갱신 주기는 기존 배터리 갱신과 같다. 메뉴 막대 창이 열려 있는 동안만 더 자주(예: 2초) 갱신해도 된다(빌더 판단, 전력 소모가 늘지 않게).

### 4. 하드웨어 잔량

- 배터리가 직접 보고하는 값 = `BatteryData.RemainingCapacity ÷ BatteryData.FullChargeCapacity`, 반올림한 정수 %. 2026-10-25 이 맥: macOS 70%, 3569 ÷ 5332 = 67%. 최상위 `AppleRawCurrentCapacity`는 이 맥(macOS 27)에 없다.
- 이름은 "하드웨어 잔량", 짧은 설명: "macOS는 배터리 보호를 위해 표시 값을 조정합니다. 이 값은 배터리가 직접 보고한 남은 용량입니다."
- 메뉴 막대 창 ⑥과 대시보드 배터리 카드에 보인다. `vbctl status --json`과 단축어 "배터리 상태 가져오기"에도 넣을지는 빌더 판단(넣는다면 기존 필드는 바꾸지 않고 새 필드로).
- 값이 없거나 0~100 밖이면 보이지 않는다.

### 5. 저전력 모드 켜고 끄기

- 메뉴 막대 창 ⑤와 대시보드(또는 충전 화면)에 스위치를 둔다. 켜면 macOS 저전력 모드를 켜고, 끄면 끈다.
- 현재 상태는 `ProcessInfo.isLowPowerModeEnabled`와 상태 변경 알림(`NSProcessInfoPowerStateDidChange`)으로 읽는다. 시스템 설정에서 바꿔도 스위치가 따라간다.
- 쓰기는 루트 권한이 필요하므로 헬퍼가 한다(아래 "헬퍼 확장").
- macOS 설정에는 "안 함 / 항상 / 배터리 사용 시에만 / 전원 어댑터 사용 시에만"이 있다. 스위치는 "지금 켜짐/꺼짐"만 다룬다. 사용자가 "배터리 사용 시에만" 같은 조건부 설정을 쓰고 있으면 스위치가 그 설정을 덮어쓴다는 사실을 스위치 옆 설명이나 확인 문구로 알린다. 정확한 `pmset` 인자(`-a`/`-b`/`-c`)와 표현은 빌더가 실기기에서 확인해 정한다.
- 헬퍼가 없거나 옛 버전이면 스위치 대신 "배터리 설정 열기" 단추와 "헬퍼를 설치하면 여기서 바로 바꿀 수 있습니다"를 보인다.
- 저전력 모드는 충전 쓰기가 아니므로 다른 충전 관리 앱이 있어도 막지 않는다. 확인은 쓰기 뒤 `isLowPowerModeEnabled`를 다시 읽어 한다. 충전 기록에는 넣지 않는다(작성자 판단).
- 단축어 동작 "저전력 모드 설정"(켜기/끄기 매개변수)을 더한다(작성자 판단: 3-1과 같은 방식이라 비용이 작고, 단축어 자동화와 조합하면 조건부 전환을 사용자가 만들 수 있다). 일정 동작과 `vbctl`에는 넣지 않는다.

### 6. MagSafe LED (조건부)

- **먼저 시험한다.** 이 맥(MagSafe 3)에서 SMC 키 `ACLC`를 루트로 쓰고 LED가 실제로 바뀌는지, 다시 "시스템 제어"로 돌려놓을 수 있는지 사용자가 눈으로 확인한다. 공개 오픈소스(batt 등)에 알려진 값은 0 = 시스템 제어, 1 = 끄기, 3 = 초록, 4 = 주황이며, 빌더가 다시 확인한다.
- **하드웨어 안전 장치**(사용자가 확인을 요청함):
  - 키 이름 `ACLC`는 코드 안의 상수다. 요청으로 키를 받지 않는다.
  - 쓰기 전에 SMC에서 키 정보(자료형과 크기)를 읽어, 예상한 1바이트 정수가 아니면 쓰지 않고 실패로 돌려준다.
  - 값은 허용 목록(0, 1, 3, 4)만 쓴다.
  - 시험 순서: 현재 값 읽기 → 끄기(1) → 사용자가 눈으로 확인 → 0으로 되돌리기 → 확인. 쓰기 오류, 예상 밖 값, 되돌리기 실패 중 하나라도 나오면 바로 멈추고 목표 6을 뺀다. 시험은 충전기를 꽂은 상태에서 한다.
  - 충전 관련 SMC 키(`CH*`, `bf*`, `CHIE` 등)는 읽기 외에 건드리지 않는다.
- 시험이 실패하거나 값이 돌아오지 않으면 목표 6 전체를 빼고 COMPATIBILITY.md에 결과를 적는다. 다른 목표는 영향을 받지 않는다.
- 성공하면: 설정에 "MagSafe LED" 선택지를 둔다.
  - **macOS 기본**(기본값): 아무것도 쓰지 않는다.
  - **끄기**: LED를 끈다.
  - **상태별로 정하기**(사용자 요청): 상태마다 초록·주황·꺼짐 중 하나를 고른다. MagSafe 3 LED가 낼 수 있는 것은 이 셋뿐이라 다른 색은 없다.

    | 상태 | 기본값 |
    |---|---|
    | 충전 중 | 주황 |
    | 상한에서 멈춤 또는 완충 | 초록 |
    | 과열로 충전 보류 | 주황 |

    배터리 사용 중(충전기 없음)에는 LED가 켜지지 않으므로 고를 것이 없다.
  - 깜빡임은 넣지 않는다. 깜빡임 값은 공개 자료로 확인되지 않았고, 확인하지 않은 값은 쓰지 않는다는 안전 장치에 어긋난다.
  - LED는 MagSafe 케이블로 연결했을 때만 켜진다. USB-C 단자로 충전하면 설정이 효과가 없다는 설명을 선택지 옆에 둔다. 시험은 MagSafe 케이블을 꽂고 한다.
- "macOS 기본"이 아닌 동안만 앱이 상태가 바뀔 때 값을 쓰고, 앱이 끝나거나 "macOS 기본"으로 돌아가면 0(시스템 제어)으로 되돌린다. 잠자기에서 깨어난 뒤에는 다시 쓴다.
- 헬퍼가 필요하다. 헬퍼가 없으면 선택지는 비활성화하고 이유를 보인다.
- **되돌리기 범위**(작성자 판단: 헬퍼에 상태를 두지 않기 위해):
  - 정상 종료: 기존 종료 처리(과열 보류 복원과 같은 자리)에서 0을 쓴다.
  - 강제 종료·충돌·덮어쓰기 업데이트: 앱이 LED 값을 썼다는 표시를 설정에 남겨 두고, 다음 실행 때 선택이 "macOS 기본"이면 0을 한 번 쓰고 표시를 지운다. 헬퍼가 연결 끊김을 감시하지는 않는다.
  - 재부팅 뒤 값이 남는지는 시험에서 확인해 COMPATIBILITY.md에 적는다. 남는다면 위의 다음 실행 처리가 덮는다.
  - `uninstall-helper.sh`는 헬퍼를 지우기 전에 0을 쓴다.
- **안전 원칙 적용**(작성자 판단):
  - 다른 충전 관리 앱(AlDente 등, 같은 LED를 제어함)이 감지되면 LED 쓰기도 막는다. 두 앱이 번갈아 쓰는 것을 피하기 위해서다.
  - 헬퍼는 쓰기 결과(SMC 호출 성공 여부)를 돌려준다. 별도 `ACLC` 읽기 요청은 만들지 않는다.
  - LED 쓰기는 충전 기록(`charge.json`, 최근 20건)에 넣지 않는다. 상한 변경 기록이 밀려나지 않게 하기 위해서다. 실패만 앱 메시지로 보인다.

## 헬퍼 확장 (사용자 동의)

- 헬퍼에 두 요청을 더한다. 각 요청은 값이 고정된 좁은 명령이고, 일반 명령 실행이나 임의 SMC 키 쓰기는 받지 않는다.
  - `setLowPowerMode(Bool)`: 고정 인자로 `/usr/bin/pmset`을 실행한다(셸 없이 argv 직접). 다른 인자는 받지 않는다.
  - `setMagSafeLED(mode)`: `ACLC` 키 하나에, 허용 목록의 값(시스템 제어, 끄기, 초록, 주황)만 쓴다. 목표 6이 빠지면 이 요청도 만들지 않는다.
- 기존 호출자 검사(콘솔 사용자, `/Applications/VibeBattery.app`, 서명 식별자)는 새 요청에도 똑같이 적용된다.
- **헬퍼 버전**: 헬퍼에 버전 읽기 요청을 더한다. 앱은 버전이 낮거나 응답이 없으면(옛 헬퍼는 새 요청을 모른다) 해당 기능을 "헬퍼 업데이트 필요"로 표시하고, 설정의 헬퍼 카드에 다시 설치 안내(`sudo …/install-helper.sh`)를 보인다. 충전 상한 쓰기는 옛 헬퍼로도 계속 동작한다.
- `install-helper.sh`는 이미 설치된 헬퍼를 교체할 수 있어야 한다(지금 되는지 빌더가 확인).
- COMPATIBILITY.md의 헬퍼 설명(할 수 있는 일, 임시 서명일 때 보안 경계가 아니라는 점)을 새 요청에 맞게 고친다.

## 하지 않는 것

- 항해 모드, 수동 방전, 덮개 닫고 방전, 교정 모드 (펌웨어가 막음).
- 잠자기 동안 충전 멈춤, 상한까지 잠자기 막기.
- 저전력 모드를 일정이나 `vbctl`에서 바꾸기.
- Developer ID 서명, 공증, 헬퍼의 팀 검사(3-4).
- 메뉴 막대 창의 색, 글꼴, 크기 꾸미기. 꾸미기는 항목 보이기와 순서, 아이콘 모양까지다.

## 실패로 보는 것

- 기능이 늘어 메뉴 막대 창이나 설정이 복잡해져 원하는 것을 찾기 어려운 상태.
- 메뉴 막대 아이콘이 실제 상태와 다르게 보이는 것(예: 상한에서 멈췄는데 번개).
- 읽을 수 없는 전력 값을 추정해 채워 넣는 것.
- 헬퍼가 고정된 요청 외의 일을 할 수 있게 되는 것.
- MagSafe LED를 바꾼 뒤 앱을 끄거나 설정을 되돌려도 LED가 macOS 기본으로 돌아오지 않는 것.
- 옛 헬퍼를 가진 사용자에게 충전 상한 쓰기까지 깨지는 것.
- 저전력 모드 스위치가 사용자의 조건부 설정을 말없이 덮어쓰는 것.
- 메뉴 막대 창 ③으로 바꾼 상한이 "다른 곳에서 바뀜"으로 오인되는 것.

## 제약

- 기존 안전 원칙: 다른 충전 관리 앱이 있으면 충전 관련 쓰기를 모두 막는다. 모든 충전 쓰기는 다시 읽어 확인하고 출처와 함께 기록한다.
- 지금까지의 원칙 "SMC 쓰기 없음"은 목표 6에서만, `ACLC` 키 하나에 한해 예외다(사용자 허용, 2026-10-25). 충전 관련 SMC 키는 여전히 쓰지 않는다.
- 화면 문구는 한국어, 쉬운 말. 내부 용어(SMC, ACLC, PowerTelemetry, pmset)는 화면에 보이지 않는다.
- 최소 macOS 15. `swift test`, `swift build`, 스모크 테스트, `scripts/build-app.sh`, CI가 계속 돈다.
- 개인 기기 값은 저장소 코드나 테스트 고정값에 넣지 않는다(이 문서의 확인 값은 기록용).

## 사용자와 정한 것

- 범위: 목표 1~5를 만들고, 목표 6은 쓰기 시험이 성공할 때만 넣는다. 잠자기 동안 충전 멈춤은 뺀다.
- MagSafe LED는 상태별로 색(초록·주황·꺼짐)을 고를 수 있게 한다.
- 메뉴 막대 아이콘 기본 모양: 아이콘 + 잔량(시안 A). 다른 두 모양은 설정에서 고른다.
- 전력 흐름: 막대(시안 B).
- 메뉴 막대 창 처음 상태: ①②③⑤⑥⑦ 보임, ④ 숨김.
- 저전력 모드와 MagSafe LED를 위해 헬퍼 역할을 넓힌다. 기존 사용자는 헬퍼를 다시 설치해야 한다.
- MagSafe LED를 위해 "SMC 쓰기 없음" 원칙에 `ACLC` 키 하나만 예외를 둔다. 하드웨어 안전 장치를 지킨다는 조건이다.

## 작성자 판단

- 상태 판단 규칙과 과열 보류 우선순위(목표 1 표).
- 하드웨어 잔량 계산식과 위치(목표 4).
- ③의 단추 값 60·70·80·90·100·끄기.
- "배터리 설정 열기"를 메뉴에서 빼고 대시보드와 ⑤ 대체 문구로 옮김.
- 단축어 "저전력 모드 설정" 추가, 일정·`vbctl`에는 넣지 않음.
- MagSafe LED 선택지 셋(macOS 기본·끄기·상태별로 정하기)과 상태별 기본값, 되돌리기 규칙.
- 헬퍼 버전 확인과 옛 헬퍼 처리.
- LED 되돌리기 범위(헬퍼 무상태, 다음 실행 때 정리), LED·저전력 모드의 안전 원칙 적용과 기록 제외.

## 빌더에게 남긴 것

- 아이콘 그리기 방법(직접 그린 이미지 또는 SF Symbols 조합), 메뉴 막대 창 크기와 간격.
- 전력 값에 쓸 키와 부호, 갱신 주기.
- `pmset` 인자와 저전력 모드 경고 문구.
- 순수 로직(상태 판단, 항목 순서 병합, 전력 막대 나누기, 하드웨어 잔량, LED 모드 결정)은 BatteryCore에 두고 테스트한다.

## 검증

- 단위 테스트:
  - 아이콘 상태 판단(넷과 과열 우선)
  - 메뉴 막대 창 항목 설정의 디코딩(옛 파일, 모르는 항목, 새 항목 추가)
  - 전력 막대 나누기(충전 중, 멈춤, 배터리 사용, 둘 다, 키 없음)
  - 하드웨어 잔량(정상, 0 나누기, 범위 밖)
  - LED 모드에서 쓸 값 결정
  - 헬퍼 요청 허용 목록(범위 밖 값 거절)
- 실기기(사용자와 함께):
  - 충전 중 / 상한에서 멈춤 / 배터리 사용에서 아이콘과 전력 막대가 맞게 보인다.
  - 메뉴 막대 창 ③으로 상한 70 → 같은 값 쓰기, 기록 출처 확인.
  - 항목 숨기기와 순서 바꾸기가 앱 재시작 후에도 유지된다.
  - 헬퍼 재설치 전: 저전력 모드에 "헬퍼 업데이트 필요", 충전 상한 쓰기는 정상.
  - 헬퍼 재설치 후: 저전력 모드 켜기/끄기가 시스템 설정과 일치한다.
  - (목표 6) LED 시험 결과, 앱 종료 시 시스템 제어로 돌아옴.
